# v0.7.0 migration map

The owner authorized publishing this safety release on 2026-10-06 (AK #6548). It is public only after the GitHub Release publish workflow succeeds and `release:verify-public` passes; check that before relying on it. Applies to consumers upgrading from published 0.6.0 or earlier, including CI, agents, parser/report consumers and target-repo operators.

## 1. New checks require unused run ids

Every `check` reserves its id before commands execute. Occupied/reserved ids cannot replace reviewed evidence; failed/interrupted reservations remain unavailable. Use a fresh id for each check. Do not overwrite signed/approved packets, recycle reservations, or copy approvals/attestations to replacement evidence.

Use the original id for downstream `report`, `explain`, `plan`, `govern` and `authorize` projections; these are not replacement checks. Update CI scripts that repeatedly call `check --run-id <fixed-id>` or use rechecking as the way to consume post-check approvals/attestations.

## 2. Every declared changed path participates in drift

Current packets include additive `changedFileDigests`, independently of source inventory `files`. Tests, config, excluded files and missing paths cannot silently escape drift denial. Preserve the field when storing/transporting packets; tolerate additive growth.

Legacy packets remain projectable, but a declared changed path without a usable recorded digest is `sha256:unrecorded` drift and cannot silently authorize. Obtain fresh evidence with a new id rather than hand-backfilling old packets. Malformed digest maps and unsupported/malformed control-plane snapshots fail closed.

## 3. Regenerate unbound witnesses

Generated witness records and receipts carry `binding.version: "1"`; outer witness version remains `"1"`. Legacy records without bindings no longer grant execution-backed support. Source/test bytes, command/timeout, runtime and selected execution context must remain current. Any current failure for the same invariant/scenario overlapping impacted source scope vetoes matching passes, regardless of timestamps or command differences.

See `docs/releases/migrations/content-bound-witnesses.md` and `docs/invariant-dsl.md`. Declare relevant test/runtime files, build first when needed, and regenerate with `witness test` or configured `witness refresh`. Do not forge historical bindings. Output symlink components and hardlinks are unsupported; proof commands must not rewrite bound inputs or create/delete context inputs during execution.

## 4. Check decisions, not exit zero

A successful CLI invocation is command completion, not an approving verdict or authorization. Use the explicit projected verdict/governance/drift and exact-run authorization assertions in `docs/ci-integration.md`. Retain lexical/execution evidence distinctions; supported witnesses alone do not approve an overall change.

## Proof and availability checklist

For the release source/package:

```bash
npm run verify
RELEASE_TAG=v0.7.0 GITHUB_REF_TYPE=tag npm run release:intent:check
npm run verify:ci --silent
```

The `RELEASE_TAG` environment check verifies intent consistency; it does not create or authorize a tag. Installed packaging replays real captured packets, including Jest missing-source denial and invalid snapshots. It is not public npm identity or accepted target adoption. The pinned 176-source Bun proof (`test/bun-scale-proof.test.mjs`) is a new Node 26 proof with this package, not a recovery of the historical Node 22 / npm `0.6.0` run.

After the GitHub Release publish workflow succeeds:

```bash
npm run release:verify-public -- --version 0.7.0
```

Then obtain target-owned normal-checkout execution/acceptance under AK #6550; do not substitute scratch compatibility packets for owner/date/control-plane/rollback acceptance. Target mutations/reruns require target-owned authority.

## Rollback

Keep reviewed packets immutable. Do not roll back by replacing runs or reusing reservations. Earlier public versions lack these safety guarantees; downgrading does not make unbound witnesses safe. Prefer a new corrected release and fresh evidence. A target may retain a pinned earlier package only under its own explicit risk decision, with the missing safeguards documented. Publishing this release activates or rolls back no target.
