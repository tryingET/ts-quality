# AI-agent migration instructions — ts-quality v0.6.0

## Start here

The breaking changes are documented in `CHANGELOG.md` under `0.6.0` → `### Breaking Changes`. Treat the changelog as the authoritative release-history surface.

Use this file as the AI-agent playbook for upgrading consumers from `ts-quality <0.6.0` to `ts-quality >=0.6.0`. The run artifact schema and CLI contract did not change; the breaking changes are the runtime floor and the license metadata.

## 1. Node.js 22 or newer

`engines.node` is now `>=22`. Node.js 20 reached end of life on 2026-04-30.

1. Find every place that runs `ts-quality` or installs it:

   ```bash
   rg "node-version|setup-node|FROM node:|\.nvmrc|\.node-version|engines|volta"
   ```

2. Move each runtime to Node.js 22, 24, or 26. CI for ts-quality itself verifies all three.
3. If a pipeline must stay on Node.js 20, pin `ts-quality@0.5.1` there and record the reason. npm only warns (`EBADENGINE`) when installing 0.6.0 on Node.js 20 unless `engine-strict` is enabled; do not ignore that warning and run 0.6.0 on an unsupported runtime.

## 2. License metadata

Package manifests now declare `"license": "SEE LICENSE IN LICENSE"` instead of `"MIT"`. The bundled `LICENSE` is the MIT License with an added rider that grants no rights to the restricted parties it names; that text, not the former `MIT` field, is authoritative.

1. Re-run any license scanner or dependency-policy check that allowlisted `ts-quality` because it declared `MIT`.
2. Route the result to whoever owns license decisions for the consuming project. An agent must not decide on its own whether the rider applies to its operator or organization.

## 3. Re-run workspace mutation evidence

Mutation workspaces now resolve package-local `node_modules` and workspace-package links to the mutated copy. On pnpm or other workspace layouts, earlier runs could report false kills (a mutant dying on `Cannot find module`) or false survivors (a sibling-package import loading the unmutated original).

1. Re-run `ts-quality check` for runs whose mutation evidence came from such layouts before trusting old verdicts or trends.
2. Expect mutation scores to move in either direction; treat the new run as the baseline. Cached mutation results from earlier versions are invalidated automatically.

## Verification

- `node --version` reports `v22` or newer wherever `ts-quality` runs.
- `npm ls ts-quality` resolves `0.6.0` without `EBADENGINE` warnings.
- License tooling reports `SEE LICENSE IN LICENSE` for `ts-quality` and the decision is recorded by its owner.
- Re-run workspace `check` results are used as the new comparison baseline.
