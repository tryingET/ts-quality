# v0.8.0 migration map

The owner authorized preparing this release on 2026-10-10 (AK #6928). It is public only after the GitHub Release
publish workflow succeeds and `release:verify-public` passes; check that before relying on it. It applies to anyone
upgrading from 0.7.0: CI scripts, agents, `run.json`/`report.json` parsers, dashboards and target-repo operators.

v0.8.0 ships the native quality wave of decision180 (S1-S4). Each part has its own detailed map:

| Part | Map |
|---|---|
| CRAP, coverage and the mutation catalog | [`legacy-quality-native-correctness.md`](legacy-quality-native-correctness.md) |
| Mutation targets, inert preview, selection ledger, time budget | [`native-selection.md`](native-selection.md) |
| Derived navigation, intervention lineage, Git facts | [`native-navigation.md`](native-navigation.md) |
| Package artifact-reference index, repo summary, release diagnostics | [`native-package-index.md`](native-package-index.md) |

## 1. Scores, symbols and site sets can move for unchanged code (breaking)

CRAP now inventories constructors, accessors and assigned functions under readable names. Complexity counts only a
function's own body, and coverage is measured over LCOV-instrumented lines. The mutation catalog adds `*`→`/`, loose
`==`↔`!=`, `++`↔`--`, `0`↔`1` and condition inversion, and no longer mutates type-only syntax. Expect more mutation
sites and different CRAP rows.

Do not compare scores across the upgrade as if they were trend. Re-run `check` with a new run id and compare runs
made by the same version. Unusable coverage is labeled `complexity[].coverageStatus`, and a changed function with
unknown coverage turns a pass into a warning.

## 2. Mutation outcomes and caching (breaking)

A test process killed by a signal is now an `error` (`errorKind: "signal"`), not a kill. Error outcomes are not
cached. The mutation runtime version moved to 9, so results cached by 0.7.0 run once more.

`run.json` gains a `mutationSelection` ledger (discovered, eligible, selected, excluded with reasons, executed,
cached, unobserved, `complete`) and per-result `origin` and `errorKind`. In CI, assert
`mutationSelection.complete === true` before trusting a mutation score. Excluded and unrun sites were never tested.

Recorded mutation output now keeps its start and its end (about 800 characters), so a failing test named at the end
of the output stays visible.

## 3. New read-only commands (additive)

- `ts-quality mutations preview [--json]`: the sites `check` would mutate, with every exclusion reason. Inert.
- `ts-quality navigate --run-id <id> [--json]`: an ordered queue of the run's open facts and inert experiments.
  `--intervention-from`/`--intervention-tests` report per-site lineage, and `--git-horizon` adds Git facts that are
  not evidence. The protected `nextEvidenceAction.primaryAction` is unchanged.
- `ts-quality index write|inspect`: the package artifact-reference index and its read-only inspection. Keep
  `.ts-quality/package-index.json` out of commits (`ts-quality retention` lists it) or write it elsewhere with `--out`.
- `check --mutation-targets` and config `mutations.targets`/`mutations.maxDurationMs` narrow and bound mutation.

## 4. Run packets (additive, with one refusal)

`run.json` gains `mutationContext` (test command, timeout, runtime, digests). A packet is staged hidden and published
with one rename together with `publication.json`. Readers refuse a published packet with missing files instead of
projecting it. Packets written by 0.7.0 have no publication record and stay readable.

## Proof and availability checklist

For the release source and package:

```bash
npm run verify
RELEASE_TAG=v0.8.0 GITHUB_REF_TYPE=tag npm run release:intent:check
npm run verify:ci --silent
npm run release:diagnostics -- --tag v0.8.0
```

`release:diagnostics` is an offline read of the release prerequisites, not permission to publish.

Local evidence before the release: one test-capabilities slice was screened with this source (S5, AK6704, evidence
14928). The native and 0.7.0 runs agreed (pass, 90/100); the native catalog found and killed 7 sites instead of 3.
That screening is local evidence, not accepted adoption of v0.8.0.

After the GitHub Release publish workflow succeeds:

```bash
npm run release:verify-public -- --version 0.8.0
```

## Rollback

Keep reviewed packets immutable and use new run ids. A target can stay pinned to 0.7.0 under its own decision. Packets
written by 0.8.0 carry additive fields that 0.7.0 readers ignore, but 0.7.0 does not check publication records.
Prefer a corrected release over downgrading.
