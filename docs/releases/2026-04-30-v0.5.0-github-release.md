# GitHub release draft — ts-quality v0.5.0

## Title

`ts-quality v0.5.0 — adoption materialization and retention guidance`

## Release body

This release is prepared through the repo's GitHub Release authority path. Publishing the GitHub Release for tag `v0.5.0` triggers `.github/workflows/publish.yml` in the `npm-publish` environment, which validates the tag/version contract, re-runs deterministic package proof, publishes the staged package to npm through Trusted Publishing/OIDC, verifies public installability, and attaches the proven tarball to the GitHub Release.

### Breaking Changes

- None.

### Added

- Added `ts-quality adopt --from-run <run-dir-or-run.json>` for turning a temporary/pilot run into repo-local reusable setup files without copying ephemeral evidence artifacts.
- Added `ts-quality retention [--config <file>] [--machine]`, including the compact `TSQ_RETENTION_PLAN_V1` protocol, to separate commit-worthy config/control-plane/witness/public-key files from generated run artifacts, latest pointers, mutation scratch files, coverage output, receipt sidecars, and private keys.
- Added a documented external `dep-diet` dogfood run covering `doctor --machine`, `retention --machine`, focused witness generation, `check`, `report`, and `explain` on a real target slice.

### Changed

- Updated README, public contract notes, and the CLI command manifest so adoption materialization and retention projection are first-class setup surfaces.
- Strengthened evidence-closure/actionability coverage around masked mutation survivors, sidecar sufficiency, and run-artifact compatibility.

### Fixed

- Hardened mutation workspace fingerprinting so symlinked excluded directories such as `node_modules` are skipped before digesting, avoiding `EISDIR` failures in temp-copy and package-manager-style dogfood setups.
- Improved compatibility coverage for older `nextEvidenceAction` packets and future additive run fields.

### Agent migration notes

- No breaking migration is required.
- For new or brownfield adoption, agents should run `doctor --machine` before inventing setup, use `adopt --from-run` when converting a pilot run into reusable repo assets, and use `retention --machine` before deciding which generated artifacts to commit or ignore.
- Private signing keys remain non-committable; `adopt` and `retention` only treat trusted public keys (`*.pub.pem`) as reusable key material.
