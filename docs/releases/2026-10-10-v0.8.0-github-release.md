# GitHub release draft — ts-quality v0.8.0

## Title

`ts-quality v0.8.0 — native quality correctness, mutation selection, navigation and package index`

## Release body

This release is prepared through the repo's GitHub Release authority path. Publishing the GitHub Release for tag `v0.8.0` triggers `.github/workflows/publish.yml` in the `npm-publish` environment, which validates the tag/version contract, re-runs deterministic package proof, publishes the staged package to npm through Trusted Publishing/OIDC, verifies public installability, and attaches the proven tarball to the GitHub Release.

### Breaking Changes
Migration map for agents and operators: [`docs/releases/migrations/v0.8.0.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/releases/migrations/v0.8.0.md), which links the per-topic maps. Decisions: [`docs/decisions/2026-10-06-legacy-quality-native-correctness.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/decisions/2026-10-06-legacy-quality-native-correctness.md) and [`docs/decisions/2026-10-04-legacy-useful-native-supersession.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/decisions/2026-10-04-legacy-useful-native-supersession.md).

- A mutation test process killed by a signal is now an `error` result (`errorKind: "signal"`) instead of a killed mutant, and error outcomes are no longer cached. The mutation runtime version moved to 9, so results cached by earlier versions are re-run once. See [`docs/releases/migrations/native-selection.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/releases/migrations/native-selection.md).
- CRAP symbols, complexity, coverage percentages and mutation site sets can change for unchanged code. Constructors and accessors gain entries, ambient/abstract/overload signatures lose them, assigned arrows and function expressions are named after their binding instead of `<anonymous@line>`, complexity counts only a function's own body, and coverage is measured over LCOV-instrumented lines. Re-run `check` with a new run id before comparing scores.

### Added
- Explicit mutation targets (`check --mutation-targets` or config `mutations.targets`: `file:`, `span:`, `symbol:`, `site:`) resolved against current source; a symbol target never mutates nested or neighboring functions, and `check` refuses unresolved command-line targets before reserving the run id or running any command (configured targets: before witnesses and mutants).
- `ts-quality navigate [--json]`: a derived, read-only blocking summary and action queue (evidence invalidity, governance, legitimacy, survivors, coverage/witness gaps, policy burden) with inert argv experiments; the protected `primaryAction` is reported unchanged. `--intervention-from`/`--intervention-tests` report per-site lineage ("observed survivor before; observed kill after declared test edit") only under an otherwise unchanged context, and `--git-horizon` adds Git facts that are not evidence. `run.json` gains additive `mutationContext`.
- `ts-quality index write|inspect`: a package artifact-reference index. It records the discovered packages, the runs holding evidence for them and the digests of their canonical packet files, plus an exact `upload.paths` list. It copies no verdict and claims no executed coverage. `inspect` reports fresh, changed or missing references, source drift, enumeration changes and findings per package, and refuses unknown schemas, paths outside the root and symbolic links. CI uploads an index built with the installed tarball and reads it back in a separate job. Repo scripts add offline release diagnostics (`npm run release:diagnostics`, never release permission) and a summary that keeps quality, verification and release facts separate, with a compare limited to comparable sections (`npm run repo:summary`, `npm run repo:summary:compare`). See [`docs/releases/migrations/native-package-index.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/releases/migrations/native-package-index.md) and the legacy crosswalk [`docs/adoption/legacy-parity/native-s4-crosswalk.md`](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/adoption/legacy-parity/native-s4-crosswalk.md).
- `ts-quality mutations preview [--json]`: an inert preview of the sites `check` would mutate, with every exclusion reason. It runs no command and writes nothing.
- `run.json` `mutationSelection` ledger (discovered, eligible, selected, excluded with reasons, executed, cached, unobserved, `complete`), result `origin` and `errorKind`, and an optional `mutations.maxDurationMs` time budget whose unrun sites are blocking `budget` errors, never clean.
- Mutation testing adds the remaining valid legacy probes: `*`→`/`, loose `==`↔`!=`, `++`↔`--`, numeric `0`↔`1` and condition inversion in `if`, `?:`, `while`, `do` and `for`. Every operator fixture of the legacy parity corpus now yields the legacy spans and replacements (`test/legacy-quality-catalog.test.mjs`).
- `complexity[].coverageStatus` names why a function's coverage is unknown (`missing`, `ambiguous`, `malformed`, `mismatched`, `not-instrumented`) or `measured`; `coverage[].malformedLines` counts unreadable LCOV `DA:` records (the file's `pct` is then 0), and `coverage[].functionHits` keeps `FN`/`FNDA` entry hits so an empty-bodied function under istanbul LCOV is measured rather than unknown. A changed function with unknown coverage adds a verdict warning, and the CRAP report, budget finding and PR summary label it as unknown instead of 0%.

### Changed
- `ts-quality retention` lists `.ts-quality/package-index.json` as a generated artifact to keep out of commits.

### Fixed
- Recorded mutation output (a failing baseline, a mutation-workspace baseline, killed and errored mutants) keeps both its start and its end, up to about 800 characters with the middle marked `…`. It used to keep only the first 280 characters, which cut off the failing test's name that test runners print last.
- An interrupted `check` no longer leaves a visible partial run packet or a torn `latest.json`: the packet is staged hidden, recorded in `publication.json` and published with one rename, and readers refuse published packets with missing files. Earlier packets without a publication record stay readable.
- Type aliases, interfaces, type parameters, `declare` declarations and `.d.ts` files no longer yield mutation sites, and a replacement that would lex together with a neighboring character (`a */* c */ b`) is skipped instead of running a different mutant.
- Repeated LCOV records for one file merge instead of producing separate coverage entries, and a function whose lines have no LCOV entries is reported as `not-instrumented` instead of a measured 0%.
- Equal-CRAP hotspots are ordered by file and line instead of input order.

### Agent migration notes
- Resolve the breaking-change migration with the [v0.8.0 migration map](https://github.com/tryingET/ts-quality/blob/v0.8.0/docs/releases/migrations/v0.8.0.md) before relying on this release in downstream agents, parsers, prompts, fixtures, or operators.
- Do not compare scores across the upgrade as trend: re-run `check` with a new run id and compare runs made by the same version. In CI, assert `mutationSelection.complete` before trusting a mutation score.
- Before release, one test-capabilities slice was screened locally with this source (decision180 S5): the 0.7.0 and native runs agreed (pass, 90/100), and the native catalog found and killed 7 sites instead of 3. This is local evidence, not accepted adoption.
