### Individual C questions: no family-label blanket acceptance

- **G1 native wave:** select the specified correctness/selection/navigation/index
  jobs in U1-U7/U9-U13/U16, or hold the native design for revision. Selection
  covers each proposed native job, not any C item: loose equality, parallelism,
  relative timeout, lookup, old interfaces, topology, diagnostics, settlement,
  declaration-level selection and aggregate coverage each have G2-G11 choices.
  Git hints are optional facts; separate indexes do not become authority.
- **G2 loose equality:** retain runtime `==/!=` probes as useful JS behavior,
  or hold until a concrete receiver establishes need. Legacy source supports it;
  no external demand was found. Runtime/type validity remains mandatory.
- **G3 parallel workers:** defer optimization until measured needed and proven
  isolation-safe, or retain as a separately measured later slice. Legacy plain
  wrapper can parallelize; planner-generated missions default to one.
- **G4 timeout-factor:** native explicit fixed budgets first; hold relative policy
  until measured need, or retain a documented opt-in factor after proof. Legacy
  ordinary execution inherits factor10; current receiver uses fixed15000ms.
- **G5 LCOV convenience:** discover/generate target-owned coverage and record the
  explicit selected path, or retain opt-in ordered lookup with provenance and
  ambiguity refusal. Historical planner genuinely relies on implicit lookup.
  Neither option accepts absent coverage as positive evidence.
- **G6 compatibility:** native interfaces and concrete adapters; hold old CLI/API/
  deep-import/types/flat JSON/mission/history/warning/declaration interfaces until
  receiver mapping or explicit discontinuation. This includes root33 aliases,
  default source/filter lookup, shell command and old exit expectations. Do not
  export unsafe executor internals merely to reproduce old barrels.
- **G7 topology:** one native package as destination, or preserve useful separate
  component design pending receiver demand. Either choice leaves existing public
  packages/tags/private migration/deprecation actions held, not accepted removed.
- **G8 release diagnostics:** retain read-only preview/inspect jobs or hold them
  pending additional operator demand. Historical publish workflow is a receiver.
- **G9 settlement:** preserve everything; create held custody/admission obligations
  for S6-S8, not executable deletion/retirement authority. Active design adoption
  does not accept legacy loss or change registration/task/routing/remote states.
- **G10 declaration-level selection:** hold automatic declaration-differential
  selection pending a receiver/job and fresh binding specification, or retain
  its usefulness as a later explicit opt-in selection mode. Exact function/span
  targeting and cache invalidation stay selected independently under G1. Neither
  answer accepts the old declaration sidecar/manual advancement interface (G6).
- **G11 aggregate coverage:** hold workspace-wide LCOV aggregation pending a
  multi-package job/provenance specification, or retain it as a separately scoped
  target-owned aggregation task. Package-index enumeration is not aggregate
  executed coverage; per-package explicit LCOV remains selected under G1/G5.
